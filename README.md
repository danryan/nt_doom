# nt_doom

A from-scratch, clean-room compact Doom engine that loads and renders real Doom WAD
content on the Expert Sleepers disting NT Eurorack module.

Can it run Doom? The P0 feasibility spikes say yes: the WAD loads byte-exact, there
is ample DRAM to hold it, and the renderer core is a small fraction of the code
budget.

This is not a port of the original Doom source. Real Doom's code is hundreds of
kilobytes; the NT caps a plug-in at roughly 82 KB of `.text` with no code offload.
So the engine is built compact from scratch, with a minimal BSP-style wall renderer
that reads geometry and textures from a real WAD. The WAD itself is delivered to the
device as a 16-bit WAV in a samples folder and read back byte-exact through the NT
sample API.

## Status

P0 feasibility spikes complete. All three viability unknowns resolved on hardware:

- WAD-via-WAV read is byte-exact (16-bit smuggle; the 8-bit path is rejected by the
  NT sample browser).
- DRAM grant is at least 12 MB per plug-in instance, ample for a WAD plus working
  buffers.
- The renderer core is about 2.4 KB of `.text`, far under the ~82 KB per-plug-in cap.

See `docs/superpowers/abort-reports/2026-06-04-doom-p0-spike-results.md` for the full
spike report and `docs/superpowers/` for the design spec and plan.

Next: P1 (load real E1M1 geometry) and P2 (real textures, floors, full BSP traversal).

## Quick start

```sh
./bootstrap.sh     # toolchain checks + submodules + python deps
make test          # host Catch2 tests (WAV wrapper, WAD parser, renderer)
make arm           # build the NT plug-ins under build/arm/
```

Deploy to hardware (NT firmware v1.13+, USB-MIDI):

```sh
make deploy-sysex SYSEX_PLUGIN=build/arm/doom_core_spike.o
```

See `CLAUDE.md` for the full build mechanics, the proven hardware constraints, and
the deploy loop.

## Layout

- `plugins/games/doom/` engine headers (WAD parse, map view, framebuffer, renderer).
- `plugins/games/doom_core_spike.cpp` renderer-core plug-in.
- `plugins/probes/` hardware spike plug-ins (SD read, DRAM grant).
- `harness/` host tools, Catch2 tests, and hardware-deploy scripts.
- `vendor/` pinned submodules (distingNT_API, llvm-project compiler-rt).
- `docs/superpowers/` design spec, plan, and spike results.
